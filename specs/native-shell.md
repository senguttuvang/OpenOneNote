# Native OneNote shell with Markdown

The supplied 31 October OneNote for Mac reference and the user's behavioural requirements govern presentation and interaction. Ordinary native rich editing is the default. Markdown remains the portable document format and a Home ribbon capability. This supersedes both the generic split workspace and the earlier Read/source-editor default without changing the portable vault, Graph identity, recovery or legacy canvas contracts.

- Keep Home/Insert/Draw/View and the observed menu families and labels. Expose unavailable features as disabled commands. Never map notebook-wide or destructive labels onto a narrower unrelated action.
- Add page immediately creates/selects a blank local page titled Untitled Page, without a naming dialog, and focuses the editable canvas title. Title changes update page navigation and persist independently of body headings. Local creation while in a Microsoft notebook explicitly navigates to On My Mac; cloud-page creation is a separate backend capability.
- Add section and every New Section menu/keyboard command immediately create/select a uniquely named local section and blank page. Select the generated name in the section row for inline replacement; never open a naming sheet. Return commits the name and focuses the page title. Escape keeps the generated name; leaving the field commits it. Reject duplicate section names without combining existing notes. Persist the section before subsequent page creation.
- Show proportional native editable text by default. Headings, bold, italic, strikethrough, links, inline code, simple lists and native table cells project onto the existing semantic tree. Native edit/format/undo/redo/save/reopen must preserve Unicode and supported semantics. Protect unsupported blocks and their retained source against rich deletion or replacement; Markdown remains their explicit editing path.
- Integrate Markdown behind the Home ribbon code icon. It reveals Write/Split/Read within the same page and shell, with no Markdown tab or top-level menu. Keep both NSTextViews mounted across toggles, preserve their selection and independent native undo histories, and target commands at the active projection. Content changes through the other projection invalidate only the stale projection's undo history. Selection-aware formatting uses UTF-16 ranges.
- Font-family/size persistence, underline, arbitrary colours, spatial objects, table structural commands and ink remain unavailable in the portable rich path. Expose accurate disabled states; do not pretend display-only settings are persisted rich formatting.
- Keep notebook, section and page navigation, native keyboard selection, search scope, width adjustment, hide/show controls, page title and reference geometry. Reflow Read at compact widths; permit horizontal scrolling for Split and wide content.
- Follow system light/dark appearance. Use measured reference neutrals, purple actions, blue headings and system symbols. Preserve visible hover/pressed/disabled/focus behavior. No proprietary artwork or client content enters the app.
- Account and notebook discovery belong in native dialogs; advanced registration metadata belongs in Preferences. Keep the auth owner's AppAuth callback/refresh and account identity APIs unchanged.
- Friendly state is a summary; sync and recovery detail preserves the existing explicit source comparison/resolution actions. New documents and hierarchy are local. Current-page sync is explicit; notebook-wide sync remains unavailable.

Acceptance: the exact-branch local check runs inline title focus/rename, native rich Unicode formatting/undo/reopen, native table insertion/cell editing, protected-source roundtrips, hierarchy/navigation invariants, observed native menu inventory, both view identities across modes, synthetic hidden renders at 1728/1280/960, ribbon tabs/modes/account dialogs and both appearances. Package verification repeats native checks. All native checks prohibit activation and leave windows hidden. Full pixel/feature parity, official transition timing, VoiceOver traversal, real popup workflows and live cloud acceptance require separate evidence; synthetic checks do not establish them.
